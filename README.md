## 30 people. The same PDF. Why 30 separate print jobs?

Picture a classroom where everyone needs the same notes. Usually, that means repeated uploads, mismatched print settings, individual orders, and a lot of unnecessary coordination.

**Pr1ntpool makes group printing feel like a group experience.**

One person uploads the PDF and sets the print preferences. Everyone else joins through a shared link, chooses a pickup slot, and gets their copies without starting from scratch. The print shop gets a clearer, more coordinated workflow too.

> **One upload → One shared pool → Everyone's copies.**

## ✦ How it works

| | Step | What happens |
| :---: | --- | --- |
| **01** | **Upload & lock** | A coordinator uploads one PDF and sets consistent print preferences. |
| **02** | **Share & join** | A single pool link brings classmates, teammates, or club members together. |
| **03** | **Choose & collect** | Participants select pickup slots while the print shop manages orders from its board. |

No duplicate document uploads. No settings confusion. **Just a simpler path from PDF to pickup.**

## Run it locally

**1. Install dependencies**

```bash
npm install
```

**2. Create a `.env` file in the project root**

```env
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_PUBLISHABLE_KEY=your_supabase_publishable_key
```

**3. Start the development server**

```bash
npm run dev
```

Open the local URL shown in your terminal.

> You'll need the project's Supabase configuration for authentication to work. Never put a Supabase secret or service-role key in a `VITE_` environment variable.

## Why we built it

The hard part of printing the same document for a group shouldn't be the printing. It should be as easy as **uploading once, sharing a link, and showing up at the right time**.

Pr1ntpool is our take on making an everyday campus problem smaller through better coordination — without asking people to change the way they already work.
